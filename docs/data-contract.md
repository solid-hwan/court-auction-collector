# 데이터 계약 v0.1

## 입력과 범위

`query`는 README의 필드만 허용한다. 법원 또는 시도가 하나 이상 필요하고 매각기일 시작·종료는 필수다. 금액은 원 단위 정수, 유찰 횟수는 0 이상 정수다. 기본 페이지는 10, 최대 100이다. 날짜 역전·음수·소수·불명확한 법원명·알 수 없는 필드는 거부한다.

`usage`는 사이트의 매각물건 검색 조건이다. `property_kind`는 반환된 개별 목적물의 대분류다. 하나의 매각물건에 토지와 건물이 함께 있을 수 있으므로 두 값이 단순 일치하지 않아도 목적물을 버리지 않는다. 응답 `usage_filter_scope=sale_item_with_associated_objects`가 이 의미를 표시한다. 지역·세부 용도 조건은 요청 매핑은 시험했지만 각각의 실조회 정확도는 미검증이다.

## 검색 행

| 필드 | 계약 |
|---|---|
| `item_key` | 법원코드 + 내부 사건번호 + 매물번호 + 목적물번호. 하나라도 필수 식별 실패 시 페이지 실패 |
| `normalized` | 법원·표시/내부 사건번호·매물/목적물 번호·감정가·최저매각가·유찰 횟수·매각기일·목적물 분류 |
| `raw` | `models.SEARCH_FIELDS` 허용목록 필드만 보존. 전체 응답 원문이 아님 |
| `missing_reasons` | null인 정규화 필드별 `missing_source_value` 또는 `invalid_source_value` 등 |

`notifyMinmaePrice1`이 존재하면 그것을 다음 공고 기일 최저가로 사용한다. 없을 때만 `minmaePrice`를 사용하고 `minimum_price_source`에 표시한다. 알려진 잘못된 값을 다른 값으로 감추지 않는다. `minmaePrice`는 이전 회차 값일 수 있다. 같은 매각물건에 속한 목적물 행에 가격이 반복될 수 있어 **행별 가격 단순 합산은 금지**한다.

금액·횟수는 음수·소수·단위 글자·잘못된 쉼표를 허용하지 않는다. 0은 유효한 원문이면 그대로 0이며 누락값을 0으로 바꾸지 않는다. 날짜는 달력 유효성을 확인한다. 원문 문자열은 변경하지 않는다. 내부 사건번호는 `YYYY0130NNNNNN`, 표시 사건번호는 `YYYY타경N`만 지원한다.

전체 건수는 `source_total_count`와 `source_total_raw`, 실패 이유 `source_total_reason`으로 분리한다. 검색 1페이지는 전체 수집 완료가 아니다. 사이트 응답에 `dlt_srchResult=[]`가 명시된 경우에만 빈 결과로 본다. JSON이 아니거나 배열이 사라지면 `schema_changed`다.

## 상세

15A만 요청한다. `dma_csBasInf.cortOfcCd/csNo`를 요청과 대조하고 누락·불일치는 실패한다. 하위 목록의 식별자가 있으면 역시 대조한다. `basic`, `sale_items`, `objects`, `events`를 분리한다.

물건별 가격은 해당 물건의 `fst/scnd/thrd/fothPbancLwsDspslPrc` 원문과 정규화 값에 남긴다. 사건의 기일 배열 순서를 가격 배열 순서로 간주하지 않는다. 기일 행의 최저가는 `null`이며 `no_verified_event_price_join`을 표시한다. 기일에 물건번호가 없으면 null로 남긴다. 관계인·전화·문서·사진·토큰 필드는 가져오지 않는다.

## 작업과 오류

SQLite `jobs`에는 변경 불가 쿼리, 시작부터 누적 요청 예약 횟수, 한도, 다음 페이지, 상태가 있다. `records`는 복합키로 중복 제거하고 `pages`의 지문과 체크포인트를 같은 트랜잭션에서 저장한다. 저장 실패 시 해당 페이지와 다음 위치를 모두 롤백한다. 요청 횟수는 요청 직전에 별도 커밋하므로 중간 종료도 한도를 되돌리지 않는다.

같은 DB의 전송 잠금은 초기 연결·재시도를 포함하여 모든 요청을 직렬화한다. 마지막 요청 시각과 차단 상태도 영속 저장한다. 파일을 없애거나 새 DB를 만들어 한도·차단을 우회하지 않는다. 별도 쿠키 파일은 없다.

`max_pages`에서 중단되면 `partial/page_limit`, 예산이면 `call_limit`, 변경된 전체 건수·조기 빈 페이지면 `source_changed`, 페이지 지문 반복이면 `repeated_page`다. `next_page`는 마지막 성공 저장 직후 위치다. `read_count`는 저장한 페이지의 읽은 행 수, `saved_count`는 고유 행 수다. 중복 페이지 오류의 행은 다시 저장·집계하지 않는다. null 전체 건수는 완전성 보증을 만들지 않는다.

`status`와 `collect` 응답의 `ok=true`는 저장 상태를 정상 조회했다는 뜻이고, 수집 완료 여부는 `status/partial/reason`으로 판단한다. `partial=true`면 CLI 종료 코드 3이다. 차단 응답은 응답 본문을 공개하지 않고 코드만 저장한다. 후속 새 작업도 같은 DB의 차단 상태를 확인한다. 단일 `search/detail`은 별도 `request_id`로 호출 예산을 기록하며 실패하면 `ok=false`다.

## 내보내기·복원

JSONL의 각 줄은 정렬된 키·ASCII 이스케이프를 사용한 완전한 공개 행이다. CSV는 `record_index,record_json`이며 JSON 객체를 문자열로 담아 수식 시작 문자를 노출하지 않는다. XLSX의 모든 셀은 명시적인 문자열 타입이다. 30,000자보다 긴 행은 `long_values`의 조각으로 보존하고 `restore_excel()`이 순서대로 합쳐 복원한다. 제어문자와 유니코드는 JSON 이스케이프로 손실 없이 복원한다. `restore_csv()`는 CSV의 긴 필드 제한을 임시로 늘리고 복원 후 원래 설정으로 돌린다.

`manifest.json`에 파일별 SHA-256과 부분수집 상태를 남긴다. 기존 목적지에는 쓰지 않는다. 요청한 출력 루트 아래 단순 이름의 폴더만 허용한다. 수집 DB의 공개 필드가 들어간 로컬 출력이며 GitHub 배포본에는 가상 예제만 포함한다.
