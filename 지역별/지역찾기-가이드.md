# 원하는 지역 찾기 — 사용자와 AI를 위한 안내

법원경매 데이터 수집기 v0.2.1 기준 · 2026-10-26 작성.

**시·도 목록 → 공식 시·군·구 목록 → 원하는 지역과 매각기일 선택 → 한 페이지 확인 → 수집·저장** 순서로 진행합니다. 전국 17개 시·도를 입력할 수 있지만 모든 지역에서 실제 물건이 반환되는지 시험한 것은 아닙니다. 지역 코드 목록 지원, 실제 조회 성공, 전체 수집 완료는 서로 다릅니다.

## 1. 사용자가 목록에서 선택하기

Python 3.11 이상을 준비하고 제품 ZIP을 푼 폴더의 터미널에서 실행합니다. 설치에는 인터넷이 필요합니다.

```bash
python setup-lab.py
python 지역별/지역선택.py
```

Linux에서 `python` 명령이 없으면 `python3`을 사용하세요. Windows도 같은 명령 형식을 쓰지만 Windows 실실행은 미검증입니다.

1. 표시된 시·도 **번호**를 선택합니다. 목록 번호와 지역 코드는 다릅니다.
2. 해당 시도의 공식 시·군·구 목록을 불러오면 원하는 항목의 **번호**를 선택합니다. `0`은 선택한 시도 전체입니다. 전국 전체를 뜻하지 않습니다.
3. 매각기일 시작·종료일을 `YYYY-MM-DD`로 입력합니다. 양 끝 날짜를 포함합니다. 게시일이나 수집일 조건이 아닙니다.
4. 저장 건수·상태·사유와 출력 폴더를 확인합니다. 자료가 저장되면 `records.xlsx`와 `지역별/지역목록.csv`에서 원하는 자료를 찾습니다.

이 실행기는 기본 1페이지, 초기 연결·코드 조회·재시도를 포함한 10회 한도를 사용합니다. 한 번 실행한 결과를 그 지역의 전체 물건 수라고 해석하지 마세요. 주소가 없는 행은 지역미확인으로 남습니다.

## 2. 지역 이름과 코드 찾기

아래 명령은 제품 폴더에서 실행합니다. Linux/macOS 기준 `.venv/bin/python`을 Windows에서는 `.venv\Scripts\python.exe`로 바꾸세요. `court_auction_mcp`는 기존 실행 호환을 위한 내부 이름입니다.

```bash
# 오프라인: 제품이 지원하는 시·도와 법원 목록
.venv/bin/python -m court_auction_mcp codes
# 온라인: 원하는 시도 하나의 공식 시·군·구 목록
.venv/bin/python -m court_auction_mcp codes --region 부산 --max-calls 3
```

두 번째 명령의 `부산`을 원하는 시도 이름이나 2자리 코드로 바꿉니다. 정상 응답은 `ok: true`, `region`, `region_name`, `districts`를 포함합니다. `districts`의 각 `name`과 `code`를 함께 확인하세요. 코드는 문자열로 보존합니다.

| 시·도 | 코드 | 시·도 | 코드 |
|---|---|---|---|
| 서울 | `11` | 부산 | `26` |
| 대구 | `27` | 인천 | `28` |
| 광주 | `29` | 대전 | `30` |
| 울산 | `31` | 세종 | `36` |
| 경기 | `41` | 충북 | `43` |
| 충남 | `44` | 전남 | `46` |
| 경북 | `47` | 경남 | `48` |
| 제주 | `50` | 강원 | `51` |
| 전북 | `52` | — | — |

표는 v0.2.1의 지원 목록입니다. 설치한 버전의 `codes` 출력이 기준입니다. 시·군·구 목록은 고정 표로 복제하지 않고 선택한 시도에 대해 실시간 조회합니다. 공식 응답의 명칭을 사용하며 현행 행정구역 전체를 보증하지 않습니다. 확인된 테스트구 `11745`는 제외되고 `excluded`에 이유가 표시됩니다.

- `district`에는 **반환된 5자리 코드**를 넣습니다. 이름·우편번호·3자리 코드를 직접 넣지 않습니다. 내부 전송용 변환은 프로그램이 처리합니다.
- `중구`, `서구`처럼 중복되는 이름은 시도부터 확정합니다. 경기의 `광주시`와 시도 `광주`도 구분합니다.
- 목록에서 도시와 하위 구가 함께 나오면 사용자가 원하는 범위의 공식 항목을 고릅니다. 상위 시 코드가 하위 구 전체를 포함한다고 추정하지 않습니다.
- 시도 전체를 원하면 `district`를 생략합니다. 법원 조건 `court`와 지역 조건 `region`은 동시에 지정할 수 없습니다.
- 동·읍·면 이름이나 임의 주소의 자동 코드 변환은 지원하지 않습니다. 시군구 조회 결과의 주소를 보고 별도로 확인하며, 주소 누락 행은 포함 여부 미확인으로 둡니다.

## 3. 한 페이지 확인하고 저장하기

아래는 **서울 강남구 예시**입니다. 날짜는 실행 시 원하는 매각기일 범위로 바꾸세요. 다른 지역은 2단계 응답에서 확인한 시도·시군구 코드로 바꿉니다. 코드·날짜를 바꾼 수집은 새 작업 ID를 사용합니다.

```bash
.venv/bin/python -m court_auction_mcp search --region 11 --district 11680 --start 2026-11-01 --end 2026-11-30 --page-size 10 --max-calls 3
```

`ok`, `status`, `query`를 확인하고 각 `records`의 `normalized.region_code`, `district_code`, `address`, `sale_date`와 `filter_check`를 살펴봅니다. `filter_check.unverified`가 비어 있지 않으면 해당 필드는 검증되지 않은 것입니다. `source_total_count: null`은 전체 건수 미확인이며 0이 아닙니다. 검색 한 페이지는 내보내기용 수집 작업을 만들지 않으므로 저장하려면 아래 `collect`를 실행합니다.

```bash
.venv/bin/python -m court_auction_mcp collect --job-id region-example-001 --region 11 --district 11680 --start 2026-11-01 --end 2026-11-30 --page-size 10 --max-pages 1 --max-calls 4
.venv/bin/python -m court_auction_mcp status --job-id region-example-001
.venv/bin/python -m court_auction_mcp export --job-id region-example-001
```

이 수동 예시는 **코드 조회 3회 + 검색 3회 + 수집 4회 = 최대 10회**로 나눠 두었습니다. 각 명령은 별도 요청/작업 한도를 사용하며 자동으로 하나의 총예산을 공유하지 않습니다. 모두 순차 실행하고 같은 DB를 사용하세요. 실제 사용량은 각 응답의 `calls`를 합산합니다. 초기 연결과 재시도도 포함됩니다. `status`와 `export`는 법원 HTTP 요청을 보내지 않습니다.

`export` 응답의 `directory`에 파일이 저장됩니다. 수동 CLI의 기본 경로는 현재 폴더의 `output/`, 선택 실행기의 경로는 제품 폴더의 `지역별/수집결과/`입니다. 작업 폴더 안의 `지역별/지역목록.csv`는 **저장된 자료의 지역 목록**이며 검색 가능한 전국 지역 목록이 아닙니다.

`partial`과 `page_limit`라면 요청한 1페이지에서 멈춘 것입니다. 사용자가 다음 페이지 수집을 요청하면 같은 작업 ID·DB로 재개합니다.

```bash
.venv/bin/python -m court_auction_mcp collect --job-id region-example-001 --max-pages 1
.venv/bin/python -m court_auction_mcp export --job-id region-example-001
```

재개해도 작업의 누적 호출 한도는 유지됩니다. `call_limit`이면 사용자가 허용한 범위에서만 `--max-calls`를 더 큰 **누적 한도**로 지정합니다. 같은 작업의 조건을 변경할 수 없습니다. 내보내기는 새 폴더를 만들며 이전 결과를 덮어쓰지 않습니다. `--db`를 지정했다면 모든 후속 명령에서도 명령 이름 앞에 같은 옵션을 둡니다.

## 4. AI에게 전달할 요청문

아래 대괄호를 채워 이 문서와 함께 전달하세요. 사용자가 지역·기간을 이미 지정했다면 다시 묻지 않아도 됩니다. 실행 도구가 없는 AI는 실행했다고 말하지 않고 명령과 확인 방법을 제공합니다.

```text
법원경매 데이터 수집기로 [시·도, 시·군·구]의 부동산을
매각기일 [시작일]~[종료일] 범위에서 찾아 Excel로 저장해줘.
지역별/지역찾기-가이드.md를 먼저 읽어줘.

1. coverage로 실제 검증 범위를 확인하고 codes로 지원 시도를 확인해줘.
2. 원하는 시도 하나의 codes(region=...) 결과에서 시군구 이름과 5자리 코드를 찾아줘.
   코드를 추측하지 말고, 동명이거나 원하는 범위를 확정할 수 없을 때만 물어봐줘.
3. 코드 조회 최대 3회, 첫 페이지 검색 최대 3회, 수집 최대 4회로 배분해줘.
   초기 연결·재시도 포함 총 10회 이내, 같은 DB에서 순차 실행하고 3초 간격을 지켜줘.
4. 먼저 10건 한 페이지의 지역·날짜·주소와 filter_check를 확인해줘.
   조건 불일치·차단·응답 변경이면 수집으로 넘어가지 말고 원인을 알려줘.
   누락값과 unverified는 추정하지 말고 따로 표시해줘.
5. 정상 확인한 조건으로 새 작업 ID를 정해 한 페이지 수집하고 파일로 내보내줘.
   저장 건수, 상태·사유, next_page, 사용 호출 수, 미확인 건수, 파일 경로를 알려줘.
6. 이번에 확인한 지역·기간만 검증했다고 보고하고 전국·전체 수집 완료라고 말하지 마.
   추가 수집·한도 증가는 요청 범위 안에서만 해줘. 차단은 우회하지 마.
```

연결된 AI 도구를 사용할 때의 순서는 다음과 같습니다. 인자는 JSON 객체이며 `district`는 직전 코드 조회의 실제 선택값으로 교체합니다.

| 순서 | 도구 | 인자 예시 |
|---|---|---|
| 검증 범위 | `auction_coverage` | `{}` |
| 시도 | `auction_codes` | `{}` |
| 시군구 | `auction_codes` | `{"region":"11","max_calls":3}` |
| 한 페이지 | `auction_search` | `{"query":{"region":"11","district":"11680","start":"2026-11-01","end":"2026-11-30","page_size":10},"page":1,"max_calls":3}` |
| 수집 | `auction_collect` | `{"job_id":"region-example-001","query":{"region":"11","district":"11680","start":"2026-11-01","end":"2026-11-30","page_size":10},"max_pages":1,"max_calls":4}` |
| 상태 | `auction_job_status` | `{"job_id":"region-example-001"}` |
| 파일 | `auction_export` | `{"job_id":"region-example-001"}` |

Python에서는 같은 처리기를 사용합니다. 예: `api = AuctionService(db="jobs.sqlite3", export_root="exports")`를 만든 뒤 `api.call("codes", {"region":"11","max_calls":3})`처럼 호출합니다. `AuctionService`는 `from court_auction_mcp import AuctionService`로 가져옵니다. 도구 표의 나머지 메서드는 `search`, `collect`, `status`, `export`, `coverage`에 대응합니다. 실제 데이터·쿠키·토큰·관계인 개인정보를 공개 문서나 Git에 넣지 마세요.

## 5. 원하는 지역을 못 찾거나 결과가 없을 때

| 상황 | 확인·다음 행동 |
|---|---|
| 시도가 없거나 `invalid_region` | `codes`의 지원 이름·코드를 사용합니다. 임의 코드 추가나 전체 지역 자동 순회를 하지 않습니다. |
| 시군구가 목록에 없음 | 시도 선택과 공식 명칭을 확인합니다. 행정구역 개편·옛 이름 여부는 법원 공식 화면에서 사람이 확인합니다. 없으면 현재 목록으로 선택 불가라고 보고합니다. |
| 목록이 비었음 | 시군구가 없다는 사실만으로 해당 시도 경매가 없다고 판단하지 않습니다. 사용자가 시도 전체를 원할 때만 district를 생략합니다. |
| `invalid_district` | 5자리 문자열인지, 선택한 시도의 코드로 시작하는지 확인합니다. |
| `ok: true`, `status: empty` | 해당 조건·시점의 빈 결과입니다. 지역 전체 경매 부재를 뜻하지 않습니다. 지역과 매각기일을 확인하고 기간 변경이 필요하면 사용자 의도를 확인합니다. |
| `filter_mismatch_*` | 해당 페이지 저장이 중단됩니다. 요청·응답 조건을 확인하고 오류를 알립니다. 다른 조건으로 자동 수집하지 않습니다. |
| `unverified`, `source_total_count: null` | 누락 사유를 보존하고 미확인으로 보고합니다. 0이나 조건 일치로 바꾸지 않습니다. |
| `page_limit`, `call_limit` | 부분수집입니다. 상태와 남은 위치를 보고하고 허용한 범위에서만 재개합니다. |
| `maintenance`, `transport_error`, `schema_changed` | 점검·통신·형식 변경을 빈 결과와 구분합니다. 반복 자동 호출을 멈추고 상태를 확인합니다. |
| `blocked`, CAPTCHA, `ipcheck=false`, HTTP 403/429 | 즉시 중단합니다. IP·브라우저·새 DB로 재시도하지 않습니다. |

문제 보고에는 버전, 실행 시각, 지역·기간, 작업 ID, `status`, `reason`, `calls`를 남기고 인증값이나 사이트 전체 응답은 첨부하지 않습니다. CLI 종료 코드 `3`은 수집 미완료·중단을 뜻하므로 상태 JSON을 읽으세요. `complete`도 관측한 끝 페이지 도달을 뜻하며 실시간 원본의 완전한 스냅샷을 보장하지 않습니다.

## 6. 실제 확인한 범위

2026-10-26 기준으로 서울 강남구 20개 목적물 저장, 경기 성남시 분당구 10개 목적물 저장을 확인했습니다. 두 지역의 매각기일 범위는 2026-11-01~30입니다. 시군구 코드 조회는 서울·경기를 확인했습니다. 그 밖의 시도는 입력 목록에 포함되지만 이번 작업에서 실조회 성공을 확인한 지역이 아닙니다.

이 문서는 새 지역을 확인하는 절차이며 전국 검증 완료 선언이 아닙니다. 날짜별 과거 시험 근거는 저장소의 `docs/regional-verification.md`, 설치 버전의 검증 범위는 `python -m court_auction_mcp coverage`로 확인합니다. 새 지역 시험 결과는 지역 코드·기간·조회 시각·페이지 수·호출 수·저장 건수·조건검증·중단 사유를 함께 기록하세요. 공개 예제에는 실제 물건 자료를 넣지 않습니다.
